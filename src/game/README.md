# 게임 모드 코드 (`src/game`)

포켓몬 패널 안에서 켜고 끄는 RPG 모드예요. TypeScript 로 쓰고 esbuild 로 묶어 `extension/` 안에 넣어요 (사용자 PC 에서는 빌드하지 않고, vsix 에 결과만 들어가요).

## 폴더 — 기능별로, 의존은 한 방향

```
core/        규칙 · 상태. 화면도 VS Code 도 Node 도 모름 → 확장 쪽 · 웹뷰 쪽 어디서든 같은 결과
  balance.ts   게임 숫자 모음 (기획 명세 4장과 1:1)
  save/        세이브 형식 · 검사(고치기) · 옛 버전 옮기기
  engine/      시간 흐름 (고정 걸음) · 시드 랜덤 · 게임 상태
  rules/       계산 함수 (피해 · 상성 · 잡기 · 경험치 …) — 단계 5부터
shared/      확장 ↔ 웹뷰 메시지 모양 (양쪽이 같은 정의)
features/    화면 하나 ≈ 폴더 하나 (model.ts = 상태 바꾸기, components/ = 화면) — 단계 3부터
ui/          같이 쓰는 화면 부품 (버튼 · HP 바 · 게이지 …) — 단계 3부터
host/        확장 쪽: 저장 (세이브 파일 · 창 잠금 · 보관함) · 웹뷰 연결 · 안 볼 때 계산
webview/     웹뷰 쪽: boot.js (늘 불러옴, 아주 작음) · game.js (게임 모드일 때만)
```

```
core  ←  shared  ←  features/*/model  ←  host
                 ←  ui · features/*/components  ←  webview
```

- 화살표 반대로는 가져오지 못해요. `npm run lint` 가 막아요 (`eslint.config.mjs` 의 `BAN`), 그리고 `tsconfig.core.json` 은 DOM · Node 타입이 없어서 `core` 에서 `document` · `process` 를 쓰면 타입 오류가 나요.
- 원래 확장(`extension/out/…`, 컴파일된 JS)은 `GAME-PATCH` 표시가 붙은 몇 줄만 고쳐요. 게임 빌드가 없거나 게임 코드가 던져도 `game-loader.js` 가 잡아서 일반 모드는 그대로예요.

## 웹뷰 생명주기

패널을 접거나 다른 탭으로 가면 웹뷰가 버려져요 (`retainContextWhenHidden` 은 메모리 때문에 쓰지 않아요). 그래서 **상태의 원본은 확장 쪽**에 두고, 누가 계산할지를 넘겨요.

```
웹뷰가 뜸 ── boot ──▶ 확장 ── load (게임 모드일 때만) ──▶ boot.js 가 game.js 를 불러옴
game.js ── ready ──▶ 확장 ── start (epoch · 상태) ──▶ 웹뷰가 계산 · 그리기를 맡음
웹뷰 ── state (1초마다, 바뀌었을 때) · save-now ──▶ 확장이 저장 (5초마다 확인 · 바로 저장)
패널이 안 보임 ── hidden (마지막 상태) ──▶ 확장이 넘겨받음
                                          자동 전투면 같은 계산을 그림 없이 이어 감, 아니면 멈춤
다시 보임 → 웹뷰가 새로 떠서 boot → ready → start (확장 상태로 이어 감)
```

- `epoch`: 계산을 맡는 쪽이 바뀔 때마다 늘어나요. 지난 epoch 의 메시지는 버려서 늦게 온 옛 상태가 덮어쓰지 않아요. 단, 확장이 넘겨받기 바로 전 epoch 의 메시지(접는 순간의 잡기 등)는 다시 맡기기 전까지 받아요.
- VS Code 밖 (창이 포커스를 잃음) + 자동 전투 꺼짐 → 확장이 `suspend` 를 보내고 웹뷰는 `hidden` 으로 답하고 멈춰요. 돌아오면 다시 맡겨요.
- 계산은 늘 같은 고정 걸음(`TIMING.simStepMs`)으로 해서, 웹뷰가 잘게 하든 확장이 크게 하든 결과가 같아요.
- 프레임 사이 시간은 0.1초, 안 볼 때 한 번에 따라잡는 시간은 1초가 상한이에요.
- 상태는 늘 새 객체로 만들어요 (그 자리에서 고치지 않음). 확장 ↔ 웹뷰 · 저장소가 같은 객체를 나눠 써도 서로 안 바뀌게.

## 세이브

- VS Code 가 이 확장에 주는 전역 저장 폴더(`globalStorageUri`)의 **`save.json` 파일** 하나 (`host/save-file.ts`). 설정 동기화에는 올라가지 않아요.
  - `globalState` 를 쓰지 않는 까닭: VS Code 를 끌 때 쓰기가 끝나지 않고 (실제 VS Code 테스트로 확인), 확장 하나에 한 덩어리라 다른 창이 다른 키를 쓸 때 옛 세이브까지 같이 다시 쓰며, 창 사이에 늦게 퍼져요.
  - 쓰기는 동기 (몇 KB 라 1ms 도 안 걸림) — 쓰기 순서가 뒤바뀌지 않고, 끌 때(deactivate)도 끝나요. 임시 파일에 쓰고 이름을 바꿔서 반쯤 쓴 파일이 남지 않아요.
- 버전 번호가 있고, 형식을 바꾸면 `save/migrate.ts` 에 옮기는 함수를 더해요. `src/test/fixtures/save-v1.json` (고정된 1판 표본) 이 늘 읽혀야 테스트가 통과해요.
- 바뀐 게 있으면 5초 안에 한 번 써요 (아무것도 안 바뀌면 타이머도 없음). 잡기 · 전투 끝 · 모드 전환은 바로, 끌 때 마지막으로.
- **창 두 개**: 게임 모드는 한 번에 창 하나 — 잠금 파일 `game-window.lock` (`host/window-lease.ts`, 없을 때만 만들기 · 그 창의 프로세스가 없으면 바로 풀림 · 30초 TTL). 세이브는 잠금을 쥔 창만 쓰고, 켤 때는 읽기만 해요. 들어갈 때 다시 읽고, 쓰기 전에 그 사이 다른 창이 썼는지(`updatedAt`) 확인해서 썼으면 덮지 않고 멈춰요.
- **보관함**: 읽지 못한 · 고쳐서 읽은 · 옮기기 전 · 더 새 버전 · 새로 하기 전 세이브의 원본은 `save-archive/` 파일로 둬요 (같은 원본은 한 번, 최근 10개). 더 새 확장에서 만든 세이브는 덮어쓰지 않아요.
- 전투가 생기면(단계 5) 전투 중에는 "전투 직전 상태 + 이번 상대(`pendingEncounter`)" 만 저장해서, 다시 열면 그 전투를 시작 모습부터 해요.

## 명령 (저장소 맨 위에서)

| 명령 | 하는 일 |
|---|---|
| `npm ci` | 개발 도구 설치 (처음 한 번, Node.js 20.9 이상) |
| `npm run watch` + **F5** | 고칠 때마다 다시 묶고, 개발용 VS Code 창에서 바로 확인 |
| `npm test` | 자동 테스트 (몇 초) |
| `npm run check` | 타입 검사 + 코드 규칙 |
| `npm run test:integration` | 실제 VS Code 를 띄워 패널 접기 · 펴기 · 저장 · 일반 모드 · 껐다 켜기 확인 (따로 된 사용자 폴더, `VSCODE_TEST_VERSION=1.73.0` 로 가장 낮은 버전) |
| `python install.py` | 빌드해서 내 VS Code 에 설치 |

주석의 `mvp-spec 3.3` · `S02 ①` · `U2` 같은 번호는 기획 문서(공개하지 않음)의 장 · 화면 · 기능 번호예요.
