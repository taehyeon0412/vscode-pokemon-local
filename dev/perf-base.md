## 재는 방법 바로잡음 (2026-11-02 #140 ① ③ — 10-30 표는 아래 넷이 섞여 있었음)
1. **문서 시계 멈춘 판** — 머리 없는 Edge 가 가끔 포커스 없이 떠 `document.timeline` 이 0 에 멈춤 → CSS 애니메이션이 안 끝나고 쌓여 50 ~ 78ms 멈칫. CDP 도구에 `Emulation.setFocusEmulationEnabled` (dev-focus 테스트) + perf-run 이 판 끝에 시계를 보고 멈춘 판은 버리고 새 브라우저로 다시 (그래도 판 15 ~ 20번에 한 번 생김 — 실제 VS Code 는 포커스가 없어도 시계가 돎: `vscode-shot.py probe=1`)
2. **게임 시계로 잰 프레임** — 기록기가 감싼 rAF 시각 (webview/clock 게임 시계) 으로 재 3:3 ×2 · ▶▶ ×3 부풀었음 → `Performance.prototype.now` 진짜 시계
3. **16ms 타이머로 그린 게임** — team-run 기본 `shim=1` 이 게임 rAF 를 16ms 타이머로 바꿔 (가상 시간 사진용) 화면 박자와 따로 그림 → 캔버스가 GPU 를 기다리며 (`RasterImplementation::Finish`) 합동 판이 100 ~ 400ms 로 크게 보였음 → perf-run 기본 `shim=0` (VS Code 처럼 화면 박자)
4. **차가운 셰이더 캐시** — 판마다 새 임시 프로필이라 처음 쓰는 그림마다 셰이더를 엮어 (ANGLE) 한 프레임 60ms 남짓 (1:1 잡기 시작 · 합동 컷인 시작 — 전 · 후 빌드 같음) → `gpucache=1` (%TEMP%/pokemon-perf-gpucache 를 판 사이로 넘김) + `warmup=1`. VS Code 는 GPUCache 를 디스크에 둬 업데이트 뒤 처음 한 번뿐 — 그 숫자는 `gpucache=0` 으로 따로 잼

## 지표
1. 50ms 넘는 멈칫 수 (100ms 넘는 것도)
2. 가장 긴 프레임 ms
3. 평균 프레임 ms · 가장 나쁜 1% (fps — 165Hz 기준)
4. 한 프레임 캔버스 그리기 수 (평균 · 최대 — 따로 한 번 더 돌려 셈 · `draws=1`)
5. 메모리 — JS 힙 · 렌더러 · GPU 프로세스 · 브라우저 전체 (사설 메모리 · 판 끝 한 번이라 ±20% 흔들림 — 흐름은 30분 켜 두기)
6. 30분 켜 두면 늘어난 메모리 (판 15)
7. 켜기 — 불러오기 시작 → 게임 손잡이 (ms)
8. 퀄리티 — 같은 순간 전 · 후 화면 픽셀 다른 비율 (+ 눈 확인)
